# Alerto — Deployment Guide

Covers Firebase backend deployment, Android/iOS release builds, and Firebase App Distribution. For local setup see the main [README](../README.md#setup).

> **Why android/ and ios/ aren't in the repo:** Flutter platform folders must be generated by the Flutter toolchain on your machine (`flutter create`). `scripts/bootstrap.sh` does this plus all Firebase wiring in one command.

## 0. One-time bootstrap

```bash
export FIREBASE_PROJECT_ID=your-project-id
sh ./scripts/bootstrap.sh
```

This generates `android/` + `ios/`, installs deps, runs `flutterfire configure`
(writes `lib/firebase_options.dart`, `android/app/google-services.json`,
`ios/Runner/GoogleService-Info.plist`), installs backend deps, sets the
Twelve Data secret, and deploys functions + rules + indexes.

## 1. Firebase (backend)

Deploy everything backend-related:

```bash
sh ./scripts/deploy-backend.sh
# equivalent: firebase deploy --only firestore:rules,firestore:indexes,functions
```

Verify:
- **Functions**: `evaluateAlerts` (scheduled, every 1 min), `getCatalog`,
  `getQuotes`, `getTimeSeries` in the console. The secret
  `TWELVEDATA_API_KEY` must be attached to the scheduled function.
- **Rules**: Firestore → Rules shows the owner-only `users/{uid}/**` policy.
- **App Check**: register Android (Play Integrity) + iOS (App Attest) apps,
  then in Firestore → Rules enable *App Check enforcement* once testers are
  enrolled (see Step 9 in the roadmap / rules comments).

## 2. Android

### Release build
```bash
flutter build apk --release            # APK for distribution
flutter build appbundle --release      # AAB for Play Store
```

### Required one-time config (in `android/`)
1. **App signing** — generate a keystore:
   ```bash
   keytool -genkey -v -keystore ~/alerto-release.keystore -alias alerto \
     -keyalg RSA -keysize 2048 -validity 10000
   ```
   Reference it in `android/key.properties` (git-ignored) and
   `android/app/build.gradle` per [Flutter's docs](https://docs.flutter.dev/deployment/android).
2. **Notification channel** — FCM high-priority messages post on the default
   channel; optionally define a named channel in `MainActivity.kt`.
3. **Package name** — `com.alerto.alerto` (set by bootstrap).

## 3. iOS

### Release build
```bash
flutter build ipa --release
```

### Required one-time config (in `ios/`)
1. Open `ios/Runner.xcworkspace`, set your **Team** and a unique **Bundle ID**
   (`com.alerto.alerto`).
2. Signing & Capabilities → enable **Push Notifications** and **Background
   Modes → Remote notifications** (required for FCM background delivery).
3. Upload APNs **key** (.p8) to Firebase console → Project settings →
   Cloud Messaging.

## 4. Firebase App Distribution

### Android (CLI)
```bash
sh ./scripts/distribute.sh android qa-testers "New alert engine + glass UI"
```

### iOS (fastlane)
```bash
cd ios && fastlane add_plugin firebase_app_distribution   # one-time
export FIREBASE_APP_ID=1:xxxx:ios:xxxx
export FIREBASE_CLI_TOKEN=$(firebase login:ci)
sh ./scripts/distribute.sh ios-fastlane qa-testers "New build"
```

### Testers
1. Create group `qa-testers` in Firebase console → App Distribution.
2. Invite testers by email; they install the App Distribution web clip / APK.
3. iOS testers must trust the ad-hoc provisioning profile on first launch.

## 5. Production checklist

- [ ] `TWELVEDATA_API_KEY` secret set and attached to `evaluateAlerts`
- [ ] Firestore rules deployed; App Check enforcement ON after tester enrollment
- [ ] `getQuotes`/`getCatalog`/`getTimeSeries` require auth (they do)
- [ ] Blaze plan active (required for scheduled functions)
- [ ] Free-tier watchlist ≤ 8 distinct symbols (see docs/MARKET_DATA.md) or
      Twelve Data paid plan
- [ ] FCM APNs key uploaded (iOS)
- [ ] Android keystore backed up securely (never committed)
- [ ] Play Store listing / TestFlight track chosen as the next step after QA

## 6. CI notes (optional)

For GitHub Actions / Codemagic, pass secrets as env vars
(`FIREBASE_CLI_TOKEN`, `FIREBASE_PROJECT_ID`, Android keystore as base64),
cache `~/.pub-cache` and `functions/node_modules`, then run the same scripts
(`sh ./scripts/deploy-backend.sh`, `sh ./scripts/distribute.sh ...`).
